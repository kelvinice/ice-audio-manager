# AGENTS.md — Working Guide for Ice Audio Manager

> Read this and the relevant doc in [`docs/modules/`](docs/modules/README.md) **before opening source files**. Full project engineering rules live in [`docs/code-practices.md`](docs/code-practices.md); if prose and code ever disagree, the **code wins** (and the PR updates the doc).

## 1. Architecture at a Glance

```
app/ui (Svelte 5 + strict TS, presentation only)
  ▲  Tauri commands / versioned events (`engine://.../v1`, `notch://.../v1`, `audio://meter/v1`)
  ▼
app/src-tauri (`#![forbid(unsafe_code)]`, thin shell, windows, tray, `iceart://`)
  │
  ▼
crates/ice-win (ALL `unsafe` & Win32/COM/GSMTC FFI, native Win32 pill)
  │
  ▼
crates/ice-core (`#![forbid(unsafe_code)]`, pure domain logic, config schema, commands/events, TS codegen)
```

- **Single source of truth in Rust:** Settings, state, and business rules live in `ice-core` / `ice-win`. The Svelte UI is pure presentation over `EngineSnapshot` and `NotchSnapshot`.
- **WebView is a resource, not a given:** Core audio, global hotkeys (`RegisterHotKey`), tray menus, and the native Win32 pill (`crates/ice-win/src/native_dot.rs`) must all function with zero WebView alive (`Lite` / gaming mode / `TrySuspend`).
- **Module index:** See [`docs/modules/README.md`](docs/modules/README.md) for the file map and owners before searching the tree.

## 2. Build, Check & Codegen Commands

> **Windows shell trap:** Always build from **PowerShell** or a **VS Developer Prompt**, **never Git Bash** (Git Bash's `/usr/bin/link.exe` shadows MSVC `link.exe`).

| Goal | Command |
|---|---|
| Full CI gate | `build check` (via `build.cmd`) |
| Build release / debug app | `build` or `build debug` (use `build run` to launch) |
| Format check | `cargo fmt --all -- --check` |
| Lint | `cargo clippy --workspace --all-targets -- -D warnings` |
| Rust tests | `cargo test --workspace` |
| Regenerate TS IPC types | `cargo test -p ice-audio-manager export_ts_bindings` *(writes `app/ui/src/lib/ipc/engine.ts` only if changed; never hand-edit generated IPC files)* |
| UI check / test / build | `npm --prefix app/ui run check`, `npm --prefix app/ui test`, `npm --prefix app/ui run build` |
| Run with fake audio devices | `target\debug\ice-audio-manager.exe --fake-engine` *(also `--start-minimized`, `--verbose`, `--show-notch`)* |

- Fresh git worktrees need `npm --prefix app/ui ci` and `npm --prefix app/ui run build` because `app/ui/dist` is gitignored and embedded by Tauri.
- Verify UI appearance changes with `npm --prefix app/ui run dev:settings` or the built app, checking 100 % & 150 % DPI and light & dark modes.

## 3. Multi-Agent Git, Worktrees & Reviews

- **Worktree per task:** Never build or commit half-done feature work directly on `main`. Work in an isolated worktree under `temp/` (e.g. `temp/ice-wt-<agent>`), run all checks, rebase onto `main`, `--ff-only` merge back to `main`, and remove the worktree and temporary branch immediately after landing.
- **No `git clean -fdx` / destructive wipes** without stopping and asking when untracked files exist.
- **Commits:** Small, single-concern commits in [Conventional Commits](https://www.conventionalcommits.org/) (`feat(scope): ...`, `fix(scope): ...`, `docs: ...`). Commit under the repository user's identity **without** `Co-Authored-By`, `Generated by`, or other AI attribution trailers.
- **Decision proposals & reviews:** When voting (`docs/votes/`) or reviewing, follow [`docs/code-practices.md`](docs/code-practices.md) §0.4 / §9 strictly (blind votes, independent findings, `severity`, file path, line, symbol, fix).

## 4. Hard Non-Negotiables (`docs/code-practices.md` §1)

1. **No global input hooks or injection:** Hotkeys use `RegisterHotKey` only — never `WH_KEYBOARD_LL`, `WH_MOUSE_LL`, or DLL/code injection.
2. **No admin / no packers:** `asInvoker` manifest; write only to `%APPDATA%\IceAudioManager` / `%LOCALAPPDATA%\IceAudioManager` / `HKCU`.
3. **Zero silent network & strict CSP:** Off by default; WebView CSP permits only `'self'` and `iceart://` (no remote URLs or `@import` in themes).
4. **MIT & Reference-never-copy (§1.8):** Read `docs/reference/` or external references only to understand OS mechanics; implement from scratch in Rust/Svelte and cite the reference in the PR. Never copy or translate code line-for-line, and keep only MIT-compatible dependencies with documented justification in `Cargo.toml` / `package.json`.
5. **Never log track titles/media PII above `debug`** and never log secrets or tokens.

## 5. Runtime, UI & Windows FFI Rules (`docs/code-practices.md` §§2–6)

- **Event-driven over polling:** Only bounded timers are allowed (cursor hit-test ≤ 30 Hz near pill; peak meter ≤ 30 Hz only while visualizer is visible), each with an explicit stop condition. Hidden = idle (`TrySuspend` in `Balanced`; zero compositor/rAF loops when suspended or hidden). Settings window is created lazily and destroyed on close.
- **Windows FFI (`ice-win` only):** Every `unsafe` block needs a `// SAFETY:` comment and RAII wrappers. Core Audio / COM callbacks run on a dedicated MTA thread, copy into a bounded channel, and never block or call back into COM. Put an explicit stop condition on background threads.
- **Styling & Theme Tokens:** Reference `--ice-*` (notch) and `--ice-set-*` (Settings) custom properties only — never hardcode literal colours or radii in `.svelte` `<style>`. Document new tokens in [`docs/theming.md`](docs/theming.md). Keep shared native pill constants/theme mapping in sync via `// Twin:` comments (`crates/ice-win/src/native_dot.rs` ↔ `app/ui/src/lib/notch/geometry.ts`, `app/ui/src/themes/base.css`).
- **Motion & compositor rules:** Use the custom `(k, c, m)` springs in `app/ui/src/lib/motion/` (never `svelte/motion`). Animate `transform`, `opacity`, `filter`, and `clip-path` only; drive pill morphs via SVG `<rect rx ry>` (`vector-effect="non-scaling-stroke"`) + `clip-path: inset(… round …)`. Always honour `systemReduceMotion` and preset `off` (`Off` = instant, no fade).
- **Capabilities & IPC:** New Tauri commands require least-privilege permissions in `app/src-tauri/permissions/` + window `capabilities/`, zero `unwrap()`/`expect()` in library or shell runtime code.

## 6. Config, Hygiene & Definition of Done (`docs/code-practices.md` §§7, 10–11)

- **Config changes:** Bump `SCHEMA_VERSION` in `crates/ice-core/src/config.rs`, add backwards-compatible migration + fixture test, preserve unknown/atomic save guarantees.
- **Testing scope:** Add minimal, focused unit/Vitest tests for new behaviour. Whole-app RAM/CPU/handle profiling and long-run leak audits run in Phase 6 (`docs/qa/`).
- **Code cleanliness:** Keep functions/components small (~60-line function, ~300-line `.svelte`, ~600-line file targets), reuse existing helpers, avoid duplication (`// Twin:` where cross-language), use `#[expect(lint, reason = "...")]` instead of `#[allow(...)]`, and tag temporary debt `// DEBT(<agent>): ...` in [`docs/plan.md`](docs/plan.md).
- **Same-PR documentation:** Every PR that changes files, public types, commands, events, config fields, threads, timers, or `--ice-*` tokens must update the corresponding doc in `docs/modules/` (with a one-line `*Change log*` entry) and run `git diff --check`.
